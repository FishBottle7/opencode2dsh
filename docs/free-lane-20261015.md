# Native adapter wire repair (2026-10-15)

This addresses [#72](https://github.com/FishBottle7/opencode2dsh/issues/72), after the session-counter fix shipped in 0.3.12. It changes the native TypeScript adapter and the admission probes that share its helpers. The unbundled legacy Go sidecar is outside this change.

## Changes

- Default base: `https://opencode.ai/inference`, also used by the live model catalog and default admission probes. Catalog/admission custom-base handling is unchanged.
- Send `x-opencode-session-id` equal to `x-opencode-session`. Existing session affinity aliases remain unchanged.
- Omit the old synthetic `x-opencode-request: req_<hex>` and `x-opencode-project: prj_<hex>` headers. Internal request IDs are unchanged; this is a wire-header change.
- Missing `bash`/`read` declarations have an optional string property. Existing empty gate schemas get that property without duplication or caller mutation. Non-empty host schemas, descriptions, and caller tool choices are preserved. Injected-only Chat tools remain call-disabled with `tool_choice: none`; Responses retains the existing `auto` behavior.

## Evidence and limits

The endpoint/session-header/schema changes follow the measurements in [Ebony-Vinyl/dsh-our-free-model#330](https://github.com/Ebony-Vinyl/dsh-our-free-model/pull/330), linked from #72 via [#310](https://github.com/Ebony-Vinyl/dsh-our-free-model/issues/310). Credit to those contributors for the initial protocol diagnosis. The OpenCode provider source also uses `/inference/v1`.

On Windows, an isolated official `opencode-ai@1.19.0` CLI and a minimal Node HTTPS request both returned `OK`. Testing the installed opencode2dsh 0.3.7 adapter with the earlier #62 session fix gave:

| Request | Result |
| --- | --- |
| Existing adapter | 403 FreeTierError |
| New endpoint + session-id header + non-empty gate schemas | 403 |
| Those changes, omitting only legacy request header | 403 |
| Those changes, omitting only legacy project header | 403 |
| Those changes, omitting both legacy headers | 200, `OK`, normal `stop` |

The installed two-bundle repair subsequently returned 200 / `OK` / `stop` on both `mimo-v2.6-flash-free` and `nemotron-3.5-lightning-free`. Requests used only the anonymous `public` credential and a fixed diagnostic message. The User-Agent, SDK headers, and session affinity aliases did not need changing in this environment.

These are observations at the stated time, not a claim about every server-side rule, region, or model. The full gateway policy is not public. Regional model restrictions and unsupported/deprecated models are separate issues.

## Regression coverage

`test/free-lane-wire.test.ts` covers the default and custom catalog base, session headers, omission of legacy synthetic headers, preservation of real schemas/tool choices, empty Chat/Responses schemas, and an actual `ZenAdapter` → pi-ai → local HTTP server request with an SSE reply. Existing session stability, reasoning recovery, and tool-result tests remain in the full suite.

Optional live verification from `packages/plugin` (uses the fixed message above and the anonymous lane, no personal key):

```sh
node test/live-issue72-check.mts --live
node test/live-issue72-check.mts --live --nemotron
```

The script requires explicit `--live`; it is excluded from the offline test suite.
